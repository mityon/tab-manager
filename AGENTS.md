# Repository Guidelines

## Project Structure & Module Organization

This repository builds a Chrome extension popup with Next.js and TypeScript. `pages/index.tsx` contains the tab list and Chrome Tabs API actions; `pages/_app.tsx` and `pages/_document.tsx` set up the app. `pages/api/hello.ts` is a Next.js API example, not part of the popup workflow. Put shared styles in `styles/`, static assets in `public/`, and extension metadata in `extensions/manifest.json`. `extensions/dist/` is generated by the export command and is ignored by Git. There is currently no test directory.

## Build, Test, and Development Commands

- Use Node.js 24 LTS and Yarn Classic (1.x). `yarn install --frozen-lockfile` installs dependencies from `yarn.lock`.
- `yarn dev` starts the Next.js development server at `http://localhost:3000` for layout work. Chrome tab actions require an extension context.
- `yarn lint` runs ESLint; `yarn tsc --noEmit` checks types.
- `yarn build` creates the production server build.
- `yarn export` creates a separate static popup build in `extensions/dist/`. Load `extensions/` as an unpacked extension in Chrome to check the popup and tab actions.
- `yarn start` serves a production build locally after `yarn build`.

## Coding Style & Naming Conventions

Use TypeScript and TSX for application code, with two-space indentation and semicolons. Keep React components in PascalCase, handlers and other functions in camelCase, and page routes in the `pages/` directory. Prefer Tailwind utility classes for popup layout; use `styles/` for reusable CSS. Keep types explicit around Chrome APIs and preserve the strict TypeScript settings in `tsconfig.json`. Run `yarn lint` before submitting changes; ESLint uses `eslint-config-next/core-web-vitals` in `eslint.config.mjs`.

## Testing Guidelines

No automated test framework or coverage target is configured. For changes to tab behavior, run `yarn lint` and `yarn export`, then load the extension and manually verify listing, activating, closing, and removing duplicate tabs. If adding automated tests, add a documented test script and name test files `*.test.ts` or `*.test.tsx` near the code they cover.

## Commit & Pull Request Guidelines

Git history currently has only an initial commit, so no commit format is established. Use short, imperative subjects that describe the change, such as `Fix duplicate tab removal`. In pull requests, explain the behavior changed, list validation commands and manual Chrome checks, link relevant issues, and include a popup screenshot for visual changes. Do not commit generated `.next/` or `extensions/dist/` files.
